# «Битва классов» — бот MAX

Python 3.12, maxo, Tortoise ORM + SQLite, Loguru, python-dotenv.
События принимаются через long polling.

## Быстрый старт в PowerShell

Установите Python 3.12 с Python Launcher и откройте PowerShell
в корне проекта. Создайте окружение и установите зависимости:

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
if (-not (Test-Path .env)) { Copy-Item .env.example .env }
notepad .env
```

Укажите `BOT_TOKEN` и сохраните `.env`. Для загрузки вопросов также
задайте `ADMIN_IDS`, например `ADMIN_IDS=[123456789,987654321]`.
Свой числовой ID можно посмотреть командой `/me` в боте.
Активация `.venv` не нужна:
мы вызываем её Python напрямую, поэтому политика выполнения
PowerShell не мешает работе и менять ExecutionPolicy не требуется.

Также поддерживаются Python 3.13 и 3.14: замените `-3.12`
на установленную версию. Python 3.15 текущий maxo не поддерживает.

Справка работает без токена и запуска бота:

```powershell
.\.venv\Scripts\python.exe src/main.py --help
.\.venv\Scripts\python.exe src/main.py -h
.\.venv\Scripts\python.exe src/main.py help
```

Команды прямого запуска:

```powershell
.\.venv\Scripts\python.exe src/main.py
.\.venv\Scripts\python.exe src/main.py --LOG_LEVEL=DEBUG
.\.venv\Scripts\python.exe -m src.main
```

Windows поддерживается напрямую. Для остановки бота нажмите Ctrl+C:
программа отменит обработчики, закроет соединения и допишет логи.
В контейнере дополнительно поддерживается остановка через SIGTERM.

## Настройки

Приоритет: `--KEY=VALUE` → `.env` → окружение → значения по умолчанию.
Пути считаются от корня проекта. Для пробелов используйте кавычки.

| Переменная | По умолчанию |
| --- | --- |
| `BOT_TOKEN` | Обязателен |
| `ADMIN_IDS` | `[]` — JSON-массив числовых ID администраторов |
| `DATABASE_PATH` | `data/bot.sqlite3` |
| `LOG_FILE` | `logs/bot.log` |
| `LOG_LEVEL` | `INFO` |

## Как проходит игра

При первом сообщении бот приветствует игрока и последовательно спрашивает
номер школы от 1 до 9999 и класс с 1 по 11 (например, `7А`). Имя берётся
из аккаунта MAX, вводить его отдельно не нужно. Затем игрок выбирает
кнопкой роль: капитан или участник. Повторный `/start` показывает текущий
этап и сохраняет команду и прогресс.

Для одной школы и класса может быть только один капитан. Он получает код
приглашения, который передаёт одноклассникам. Участник вводит этот код;
бот проверяет школу и класс и отправляет капитану запрос на вступление.
Капитан подтверждает или отклоняет заявку. При отказе участник может ввести
код повторно. До вступления в команду можно вернуться к выбору роли.

Команда вмещает до 30 игроков вместе с капитаном. Капитан тоже выполняет
задания. Когда состав собран, капитан нажимает «Начать игру». С этого момента
вступление закрывается, а состав команды и задания всех трёх раундов
сохраняются в БД. Уведомление о старте получают игроки команды.

Состав показывается нумерованным списком: `№1. Имя — @username`.
Если у игрока нет username, вместо него выводится `юзернейм не указан`.
Даты в сообщениях отображаются по московскому времени, например
`9 ноября 23:59`.

Игра длится 72 часа с момента старта конкретного класса: три раунда по
24 часа. Переход к следующему раунду определяется автоматически по времени,
в том числе после перезапуска бота. Задание текущего раунда игрок получает
кнопкой «Выполнить задания на сегодня» или командой `/tasks`.

В каждом раунде каждый игрок получает один индивидуальный вопрос.
Внутри команды вопросы раунда не повторяются. Ответ нужно отправить
самостоятельно; исправлять неверный ответ можно до конца раунда.
Правильный ответ засчитывается один раз. За раунд класс может набрать
100 баллов: вес задания равен `100 / число игроков`. Например, для
20 игроков одно выполненное задание приносит 5 баллов. Максимум за игру —
300 баллов. Пропущенные задания не приносят баллов. Текущий счёт и итоги
доступны кнопкой или командой `/results`.

Регистрация, заявки, состав команды, время старта, выданные вопросы и
правильные ответы сохраняются в SQLite. Перезапуск бота не начинает игру
заново.

| Команда | Действие |
| --- | --- |
| `/start` | Приветствие и текущий этап регистрации или игры |
| `/help` | Правила и доступные команды |
| `/me` | Профиль игрока и его MAX ID |
| `/team` | Команда; для капитана также ожидающие заявки и управление стартом |
| `/tasks` | Индивидуальное задание текущего раунда |
| `/results` | Баллы команды по раундам и общий результат |
| `/admin` | Инструкция загрузки вопросов для администраторов |
| `/media раунд номер` | Администратору: привязать аудио или фото к вопросу |
| `/next_round [код]` | Администратору: завершить текущий раунд |

## Вопросы и администрирование

Банк вопросов и медиа наполняется администратором через чат с ботом.
При первом запуске новая база пуста. При каждом запуске бот отправляет
пользователям из `ADMIN_IDS` сообщение «Бот запущен», количество вопросов
и состояние медиа для всех трёх раундов. Если хотя бы один раунд не готов,
игра заблокирована до загрузки недостающих материалов. Ошибка доставки
одному администратору не мешает уведомить остальных.

Кнопка помощи и команда `/help` показывают правила и команды игрокам.
Администраторы дополнительно видят инструкции по наполнению банка,
настройкам окружения и текущую готовность каждого раунда. Команда `/admin`
также открывает административную справку.

В `.env` или окружении задаются `BOT_TOKEN` — токен бота и `ADMIN_IDS` —
JSON-массив числовых ID администраторов, например `[123456789,987654321]`.
Полный список параметров приведён в таблице настроек выше.

Администратор из `ADMIN_IDS` отправляет боту текстовый файл как вложение.
Разрешены только имена `r1.txt`, `r2.txt`, `r3.txt`; имя определяет
заменяемый раунд. Кодировка — UTF-8 (в том числе с BOM), строки чередуются:

```text
Вопрос первого игрока?
Ответ на первый вопрос
Вопрос второго игрока?
Ответ на второй вопрос
```

Размер TXT — до 1 МБ. Пустые строки и неполные пары не допускаются.
Переводы строк Windows и UTF-8 с BOM поддерживаются. Некорректный файл
отклоняется целиком; корректный атомарно заменяет банк выбранного раунда
и удаляет его старые привязки медиа. После каждой загрузки нового TXT
загрузите медиа этого раунда заново.

Раунд 1 содержит текстовые вопросы. Для **каждого вопроса** раунда 2
нужно аудио, для каждого вопроса раунда 3 — изображение. Сначала загрузите
TXT, затем отправьте соответствующее медиа одним из способов:

- Документ `r2_N.mp3` для аудио вопроса N второго раунда.
- Документ `r3_N.jpg` для изображения вопроса N третьего раунда.
- Аудиосообщение с подписью `/media 2 N`.
- Изображение с подписью `/media 3 N`.

Номера вопросов начинаются с 1 и соответствуют порядку пар в TXT.
Например, `r2_1.mp3` относится к первому вопросу из `r2.txt`, а подпись
`/media 3 5` связывает отправленное изображение с пятым вопросом `r3.txt`.
Медиа сохраняется в БД как токен вложения MAX и отправляется игроку
вместе с заданием.

Старт разрешён, когда все три банка содержат вопросы, у каждого вопроса
второго раунда есть аудио, а у каждого вопроса третьего — изображение.
Кроме того, в каждом банке должно быть не меньше вопросов, чем игроков
в команде. Для команды из 30 игроков загрузите минимум по 30 вопросов
и заполните все соответствующие медиа. Если условие не выполнено,
бот сообщает капитану причину блокировки старта.

При старте фиксируются тексты, ответы и медиа заданий всех трёх раундов.
Загрузка новых текстов или замена медиа меняет банк для будущих игр;
уже начатые игры продолжаются с сохранёнными заданиями и результатами.

Для проверки игры администратор из `ADMIN_IDS` может вручную завершить
текущий раунд командой `/next_round`. Без аргумента команда действует
на его собственную команду; с кодом приглашения — на соответствующий
класс, например `/next_round ABCDEF01`. Игра должна быть уже начата.
Последовательность переходов: первый раунд → второй → третий → завершение
игры. После перехода на второй или третий раунд у игроков есть новые
24 часа. Назначенные вопросы, сохранённые ответы и заработанные баллы
сохраняются. Команда не перезапускает завершённую игру и недоступна
игрокам, чьи ID не указаны в `ADMIN_IDS`.

## Разработка

Обработчики находятся в `src/handlers`, бизнес-правила — в `src/game.py`,
импорт вопросов и медиа — в `src/questions.py`, форматирование дат —
в `src/presentation.py`, тексты сообщений и команды — в `src/texts.py`.
Уведомления о запуске находятся в `src/startup.py`. Middleware передаёт
профиль MAX-пользователя из БД параметром `profile: User` и последовательно
обрабатывает события одного пользователя. Дубликаты событий отсекаются
в памяти на время `PROCESSED_UPDATE_TTL`; после перезапуска эти отметки
теряются. Повторные действия дополнительно проверяются бизнес-логикой.

Таблицы создаются при запуске. Новые игровые таблицы дополняют существующую
базу пользователей; последующее изменение схемы таблиц требует миграций.
Логи пишутся в stderr и файл, ротация — 10 МБ, хранение архивов — 7 дней.

## Запуск на Windows 10 через Docker Desktop

Установите и запустите [Docker Desktop][docker].
Требования к версии Windows указаны в инструкции установки.
Python и `.venv` на стороне Windows для этого способа не нужны.

Откройте PowerShell в корне проекта и подготовьте `.env`:

```powershell
if (-not (Test-Path .env)) { Copy-Item .env.example .env }
notepad .env
```

Заполните `BOT_TOKEN` и при необходимости `ADMIN_IDS`.
По умолчанию образ — `python:3.12-alpine`.
В PowerShell перенос строки обозначается обратным апострофом:

```powershell
docker build -t maxbot .
docker build -t maxbot:slim `
  --build-arg BASE_IMAGE=python:3.12-slim .
docker run --rm maxbot --help

docker run -d --name maxbot `
  --env-file .env `
  --mount type=volume,source=maxbot-data,target=/app/data `
  --mount type=volume,source=maxbot-logs,target=/app/logs `
  maxbot

docker logs -f maxbot
docker stop --timeout 30 maxbot
```

Volumes сохраняют БД и логи после удаления контейнера.
`.env` не включается в образ; значения передаются через `--env-file`.
Для переопределения добавьте `--KEY=VALUE` после имени образа.
Банк вопросов, привязки медиа и выданные задания сохраняются в БД
внутри volume `maxbot-data`. Материалы загружаются через чат с ботом
после запуска контейнера.

Сборка: системные пакеты (`apk`/`apt-get`), venv с библиотеками,
пользователь и права. Компиляторы остаются в промежуточном образе.
UID/GID по умолчанию — `10001:10001`; аргументы сборки —
`APP_UID` и `APP_GID`. Запускайте один процесс для одного токена.

[docker]: https://docs.docker.com/desktop/install/windows-install/
